= Ammitto China sanctions data

This repository maintains Chinese sanctions and countermeasure announcements
as YAML for Ammitto. Contributors transcribe Ministry of Foreign Affairs
(MFA) and Ministry of Commerce (MOFCOM) announcements into `sources/`, with
one file per official announcement and its source URL.

== Source

* Ministry of Foreign Affairs (MFA), anti-sanction list and countermeasures (反制裁清单和措施): https://www.mfa.gov.cn/web/wjb_673085/zfxxgk_674865/gknrlb/fzcqdcs/
* Ministry of Commerce (MOFCOM), which publishes the Unreliable Entity List (不可靠实体清单) and the Export Control List (出口管制管控名单) announcements: https://www.mofcom.gov.cn/

China publishes these lists as individual announcements, not as one
downloadable file. Each file here records the URL of the announcement it was
transcribed from (`announcement.url`).

The three lists covered:

* Anti-Sanction List (`cn/anti-sanction-list`), MFA
* Unreliable Entity List (`cn/unreliable-entity-list`), MOFCOM
* Export Control List (`cn/export-control-list`), MOFCOM

== Contents

The data is in `sources/`:

* `sources/sanction-lists/anti-sanction-list/`: MFA decisions, named after the publication date, such as `20251226.yml`
* `sources/sanction-lists/unreliable-entity-list/` and `sources/sanction-lists/import-export-control-list/`: MOFCOM announcements, named after the year and announcement number, such as `202501.yml` for 〔2025〕1号
* `sources/sanction-updates/unreliable-entity-list-updates/`: announcements that suspend or end earlier measures, named after the date
* `sources/legal-instruments/`: the laws and regulations the announcements cite
* `sources/supporting/`: identifiers for the lists, publishing bodies and document types used in the files

The schemas for these files are in `schemas/`. `reference-docs/` holds the
original Chinese texts as Markdown.

An announcement file in `sources/sanction-lists/` has two parts:

[cols="1,1,3"]
|===
| Key | Type | Meaning

| `announcement.title` | list | Title, in Chinese (`zh-Hans`) and English (`en`)
| `announcement.url` | string | Official URL of the announcement
| `announcement.publish_date` | string | Publication date, `YYYY-MM-DD`; `publish_time` when known
| `announcement.authority`, `publisher`, `signatory` | string | Issuing body, as an identifier from `sources/supporting/organizations.yml`; in a few files `signatory` is the signing official's name, with `signatory_title`
| `announcement.type` | string | Document type, as an identifier from `sources/supporting/document-types.yml`
| `announcement.document_id` | string | Official document number, such as `第19号`
| `announcement.content` | string | Full text of the announcement, in Chinese
| `sanction_details.instruments` | list | Laws cited: an `id` naming the law and, where cited, `articles`
| `sanction_details.entities` | list | The listed parties, described below
|===

Each entry in `sanction_details.entities`:

[cols="1,1,3"]
|===
| Key | Type | Meaning

| `name` | map | Name in Chinese (`zh-Hans`) and, where available, English (`en`)
| `type` | string | `organization` or `individual`
| `title` | map | Individuals: position, in Chinese and English, where given
| `gender` | string | Individuals: `male` or `female`, where given
| `sanction_list` | string | Which list: `cn/anti-sanction-list`, `cn/unreliable-entity-list` or `cn/export-control-list`
| `effective_date` | string | Date the measures take effect
| `reason` | list | Reason given, in Chinese and English
| `measures` | list | Each measure in Chinese and English, with `type`, a list of codes such as `asset_freeze`, `prohibit_transactions`, `entry_ban` or `export_license_requirement`
|===

Files in `sources/sanction-updates/` carry `measure_modifications.modifications`
instead: each with `action` (such as `suspend`), the announcement it applies
to (`target_announcement_id`, `target_announcement_date`), `effective_date`,
`until_date` where set, and `notes`.

The files use YAML anchors to repeat shared reasons and measures, so a loader
must allow aliases.

== Harmonized field mapping

The https://github.com/ammitto/ammitto/blob/74491e856c1e68aea52c0cf0e34061d48429d359/lib/ammitto/sources/cn/transformer.rb[China transformer] reads announcement and measure-modification documents. Entity paths below are relative to `sanction_details.entities[]`.

Targets below use canonical Ruby fields. Entity classes are under
`Ammitto::Ontology::Entities`; `SanctionEntry`, `OfficialAnnouncement`,
`SanctionReason` and `SanctionPeriodModification` are under
`Ammitto::Ontology::Sanction`; other target classes are under
`Ammitto::Ontology::ValueObjects`. JSON-LD uses the serializer's wire keys:
`SourceReference.fetched_at`, for example, is published as `retrievedAt`.

[cols="2,3,4",options="header"]
|===
| Input field | Canonical target | Transformation

| `name.en`, `name.zh-Hans`
| `Entity.names` → `NameVariant.full_name`, `script`, `is_primary`
| Keeps English and Chinese variants; English is primary when present.

| `type`, `gender`
| `PersonEntity` or `OrganizationEntity`; `PersonEntity.gender`
| Uses the source party type; copies gender for persons.

| `announcement.document_id`, entity name, `sanction_list`
| `Entity.id`; `SanctionEntry.id`, `regime`
| Derives collision-aware party references and list-qualified entry IRIs; export-control announcement IRIs include their list.

| `measures[].type`, localized measure text
| `SanctionEffect.effect_type`, `localized_descriptions`
| Uses the first type of each measure and retains language/script metadata; absent measures use `sectoral_sanction`.

| `reason[]`
| `SanctionEntry.reason_details` → `SanctionReason.localized_descriptions`
| Keeps language-keyed reasons as localized values with category `other`.

| `effective_date`, `effective_time`
| `TemporalPeriod.effective_date`, `effective_time`, `is_indefinite`
| Parses the date, retains the time, and marks the period indefinite.

| `announcement.title`, `url`, `publish_date`, `publish_time`, `document_id`
| `OfficialAnnouncement.title`, `url`, `publish_date`, `publish_time`, `document_id`
| Title prefers Chinese, then English; dates are parsed separately from publication times.

| `sanction_details.instruments[]`
| `LegalCitation`
| Builds citations and legal-instrument IRIs from the supplied identifiers or law.

| `measure_modifications.modifications[]`
| `SanctionPeriodModification.target_announcement_id`, `action`, `effective_date`, `until_date`
| Builds target notice IRIs using the announcement naming rule (list-qualified for `export_control`) and retains action, dates, times and notes.
|===

== Using the data

Clone or download this repository and run either example from its root
directory. The Python example requires PyYAML
(`python3 -m pip install PyYAML`).

Ruby:

[source,ruby]
----
require "yaml"

Dir.glob("sources/sanction-lists/**/*.{yml,yaml}").sort.each do |path|
  doc = YAML.safe_load_file(path, aliases: true)
  date = doc["announcement"]["publish_date"]
  doc["sanction_details"]["entities"].each do |entity|
    name = entity["name"]["en"] || entity["name"]["zh-Hans"]
    puts [date, entity["sanction_list"], entity["type"], name].join("\t")
  end
end
----

Python:

[source,python]
----
import glob
import yaml

paths = glob.glob("sources/sanction-lists/**/*.yml", recursive=True)
paths += glob.glob("sources/sanction-lists/**/*.yaml", recursive=True)
for path in sorted(paths):
    with open(path, encoding="utf-8") as f:
        doc = yaml.safe_load(f)
    date = doc["announcement"]["publish_date"]
    for entity in doc["sanction_details"]["entities"]:
        name = entity["name"].get("en") or entity["name"]["zh-Hans"]
        print(date, entity["sanction_list"], entity["type"], name, sep="\t")
----

The same lists, harmonized with the other sources into JSON-LD:
https://www.ammitto.org/api/v1/sources/cn.jsonld

== Updates

This repository is maintained by hand: a new announcement is transcribed into
a new file under `sources/`.

== Maintaining the data

After transcribing an announcement, use Ruby and Bundler to install the
link:Gemfile[Gemfile] dependencies and run the validation wrapper from the
repository root:

[source,shell]
----
bundle install
bundle exec ruby scripts/validate_cn_data.rb
----

link:scripts/validate_cn_data.rb[The wrapper] delegates validation to the
Ammitto gem. The source schemas are in link:schemas/[schemas/]; preserve the
official text in `reference-docs/` and the announcement URL in each YAML
record when updating the data.
